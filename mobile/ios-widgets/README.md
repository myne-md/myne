# Myne iOS Widgets (SwiftUI / WidgetKit)

Native widget UI for the Myne mobile client, reproducing the `Myne iOS Widgets`
design board. **UI only — no logic.** These are SwiftUI sources kept in the repo
because the Tauri-generated Xcode project at `src-tauri/gen/apple/` is
regenerated by `tauri ios init` and is git-ignored; you wire these in as a
**Widget Extension target** (steps below).

## Design principle (load-bearing)

> The widget process runs **outside** the trust boundary that holds plaintext.
> While the device is locked the vault key is unreachable, so there is
> structurally nothing to show. The set is therefore launchers, one capture
> action, and a generic locked state — and nothing else. Richness here would be
> a leak.

So: **no note titles, previews, counts, streaks, or timestamps** anywhere. The
"deliberately excluded" panel of the design board (recent notes, counts, search,
"vault unlocked" status, Live Activity) is excluded here too — on purpose.

## What's here

```
ios-widgets/
├── MyneWidgets/                 ← the Widget Extension target
│   ├── MyneWidgetBundle.swift   ← @main WidgetBundle
│   ├── HomeWidgets.swift        ← WG-01 Open · WG-02 Quick capture (S/M) · WG-03 Encrypted
│   ├── LockScreenWidgets.swift  ← accessoryInline / Circular / Rectangular + WG-05 StandBy
│   ├── MyneControl.swift        ← WG-02 Control Center control "New note" (iOS 18+)
│   ├── CaptureIntent.swift      ← NewNoteIntent (Action Button + control), opens the app
│   ├── MyneColor.swift          ← design tokens (mirror of src/styles/tokens.css)  [SHARED]
│   └── MyneMark.swift           ← the Myne "M" mark Shape + logo tile              [SHARED]
└── MyneApp/
    └── CaptureSheet.swift       ← WG-04 quick-capture surface (typing/voice/saving)
                                    — belongs to the APP target (holds plaintext)
```

`MyneColor.swift` and `MyneMark.swift` are used by both the extension and the
app-side `CaptureSheet`; add them to **both** targets' membership (or factor them
into a shared Swift package).

## Wiring into the Tauri iOS project

`tauri ios init` already generated `src-tauri/gen/apple/myne-mobile.xcodeproj`.
To add the widgets:

1. Open `src-tauri/gen/apple/myne-mobile.xcodeproj` in Xcode.
2. **File → New → Target… → Widget Extension**, name it `MyneWidgets`
   (uncheck "Include Live Activity"; check "Include Configuration Intent" off —
   these are `StaticConfiguration`). Bundle id `md.myne.mobile.widgets`.
3. Delete the stub files Xcode created; **add** the files under
   `ios-widgets/MyneWidgets/` to the new target (drag in, "Create groups",
   target membership = `MyneWidgets`). Add `MyneColor.swift` + `MyneMark.swift`
   to the **app** target too.
4. Add `ios-widgets/MyneApp/CaptureSheet.swift` to the **app** target and present
   it from the `myne://capture` route.
5. Register the `myne://` URL scheme on the app target (Info → URL Types) so the
   `widgetURL` / `NewNoteIntent` open routes resolve.
6. The Control Center control + Action Button need **iOS 18**; the bundle gates
   `NewNoteControl()` behind `if #available(iOS 18.0, *)`.

> Because `gen/apple/` is regenerated, re-running `tauri ios init` drops the
> manually-added target. For a durable setup, either keep a checked-in Xcode
> project patch, or add the extension via the Tauri project's `project.yml`
> (xcodegen) so it survives regeneration. Tracked as a Phase-3 follow-up.

## Preview

Each widget view + the capture sheet carry `#Preview`s, so you can render them in
the Xcode canvas without a full build. The home/lock/StandBy surfaces follow the
system light/dark appearance via the dynamic `MyneColor` tokens.
