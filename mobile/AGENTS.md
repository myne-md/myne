MYS1 **search runs Rust-side** (`myne_core::search` BM25 engine, frontend-fed — the WebView already holds every note's plaintext, so it pushes the corpus down rather than the Rust core decrypting). Command *bodies* live in the repo-root `core/` crate (shared desktop↔mobile); the mobile `plugins/` are thin re-export wrappers. The `protocol/` crate is a direct path-dependency — zero crypto reimplementation, so `protocol/tests/vectors.rs` (the `myne-test-vectors` runner) validates mobile's blob/crypto path for free.

## Stack — Tauri 2 Mobile

- **Tauri 2 Mobile** for both iOS and Android (shared shell, native packaging per platform)
- **Reuses `protocol/` Rust crate directly** from the main repo — no port, no separate libsodium binding to audit, no second crypto codebase
- **Reuses React UI** from main repo `src/` — no second UI codebase to maintain
- pnpm + pinned Node (`.nvmrc`); same toolchain as main repo

### Why Tauri Mobile (not React Native, Flutter, Expo, or native split)

Per project's reproducible-build + minimal-trust-surface discipline:
- **One Rust crypto crate, three platforms** — `protocol/` is `#![no_std] + extern crate alloc;` specifically so it compiles for desktop + mobile + (future) wasm-web. No second implementation to audit.
- **One React UI codebase** — desktop screens (`src/screens/`) reuse straight to mobile; per-platform layout tweaks are CSS, not separate codebases.
- **Single trust boundary surface** — Tauri's permission ACL (`capabilities/default.json`) extends to mobile capabilities; same scoping discipline.
- **Cross-platform frameworks add a third runtime + their own crypto wrappers** — RN/Flutter/Expo each introduce a JS bridge (or Dart VM) layer that must be audited as a trust boundary on top of native crypto. Tauri Mobile is closer to "Rust binary + WebView", which is the existing trust model.
- **Native iOS Swift + Android Kotlin** would mean three crypto codebases (Rust desktop + Swift iOS + Kotlin Android), each requiring its own libsodium binding, each a separate audit surface. The "no custom primitive implementations" rule survives but the "single auditable codebase" advantage evaporates.

### Trade-offs to surface (pre-Phase-3 design pass)

- **Tauri Mobile is newer** (Tauri 2.x feature, GA in 2024) than the desktop track. Phase 3 start should re-verify maturity, App Store / Play Store distribution story, and known issues vs. the ~year-of-experience desktop track.
- **WKWebView (iOS) ≠ WebView (Android) ≠ Chromium (desktop)** — feature parity gaps exist (CSS, fonts, storage quotas, gesture handling). Test all three.
- **Mobile-specific UX** (offline-first sync indicators, biometric vault unlock, file-picker for Obsidian import, share-extension for "Save to Myne") is real product work that doesn't reuse from desktop.

## Cross-implementation discipline

- Same `protocol/` Rust crate as Phase 1 desktop — primitives are bit-identical by construction, not by parallel implementation
- `myne-test-vectors/` companion still validates the underlying primitives as regression coverage; new vector failures stop-the-world for ALL clients (since they share the crate)
- Phase 2 Go server's primitives (separate codebase, validated via vectors) are the only client-vs-server vector gate

## Phase parity (NOT a goal at start)

Phase 3 mobile is the **minimum viable** read+write client. Feature parity with desktop is not a goal at launch — establish core flow first (vault unlock, note read, note edit, sync). The codebase reuse means parity creeps closer naturally over time.

## Hard architectural commitments (apply to all clients)

- No email at signup, no email recovery
- No plaintext mode, no encryption opt-in
- No telemetry / analytics — App Store + Play Store will push toward analytics SDKs; **resist them** or document the explicit exemption in main repo `docs/decisions.md`
- Reproducible builds — mobile build determinism is harder (Xcode/Gradle environment variability) but still a goal; document the recipe in `myne-ops/`

## The platform seam under `mobile/src` (myne#492)

`mobile/src/platform/` is the ONE place under `mobile/src` allowed to import `@tauri-apps/*`. **Five**
modules, one per host capability: `core`, `event`, `path`, `window`, `deepLink`. Everything else under
`mobile/src` imports from there. (This paragraph said six and listed a `clipboardManager`, and BOTH were
right when written: `clipboardManager.ts` landed with the seam in `f643633c` on 2026-08-15 and was
removed in `48f06b73` the next day, when clipboard writes moved to the sensitive-clipboard plugin.
The paragraph was never updated. It is the count that went stale, not the history, and saying the
module "never existed" would be a worse error than the one it replaced, because this sentence exists
to stop the next reader restoring it. `docs/glossary.md`'s **platform seam** entry carried the same
six for the same reason.)

**`path` is the one member that is not a re-export**, and the difference is load-bearing rather than
stylistic. It was `export { documentDir, join } from "@tauri-apps/api/path";` until myne#517, and
four export flows each composed `join(await documentDir(), name)` before relying on a startup hook
having excluded that directory from the platform's automatic cloud backup. It is now a single
`exportPath(filename)` over `plugin:export-dir|export_path`, which resolves the directory, creates
it, applies the exclusion and sanitizes the filename in one host-side call and returns a path only
when all four succeeded. Two consequences worth knowing before editing anything here:
`core:path:default` is **gone** from `capabilities/default.json`, so `plugin:path|*` is unreachable
rather than merely unused; and re-adding a raw accessor to this file still COMPILES, because
`check-platform-seam.mjs` permits this directory to import `@tauri-apps/api/path` by design.
`scripts/check-mobile-export-backup.mjs` rule 0 is the only thing that refuses it, and it refuses
`documentDir` too. `docs/decisions/security/0595`. `scripts/check-platform-seam.mjs` enforces it
in `pre-commit` and in CI, so `--no-verify` does not slip one through, and it fails on the runtime
global (`__TAURI…__`) too, which is not a module specifier and so slips the import rule. Exactly one
file per client may name that global, and here it is `mobile/src/lib/app-window.ts`.

**The reason is not the desktop reason.** Desktop's seam exists so the web client can substitute a
wasm-Worker implementation behind it. Nothing substitutes behind mobile's: mobile is a Tauri host on
both of its targets. It exists so the guard has a boundary to enforce at all, and so the twin
modules under `mobile/src/lib` stay byte-identical to their desktop counterparts, which is how a fix
to one reaches the other. Before this, 41 files here imported Tauri directly and four of them
differed from their desktop twin in the import line and in nothing else.

**`mobile/src/formfactor/` is a different thing that used to share this name.** It holds the
iOS-versus-Android and phone-versus-tablet PRESENTATION split (`PlatformContext`,
`SizeClassContext`, `theme`) and was renamed out of the way, so `<tree>/platform/` means the host
seam in all three clients. A path from before 2026-08-15 naming `mobile/src/platform/SizeClassContext.tsx`
resolves to a real directory holding something else entirely, which is worse than a dangling one.
Full rationale: `docs/decisions/clients/0497-*`.

## Gotchas

- **App icons: `gen/` is regenerated with STOCK Tauri icons** — the committed Myne set lives in `src-tauri/icons/{ios,android}`, but every `tauri [ios|android] init` re-stamps the git-ignored `src-tauri/gen` with the default Tauri logo. `scripts/sync-icons.sh` restores the Myne set: it runs automatically on every dev/build (`tauri.conf.json` before-hooks → `pnpm sync-icons`) and from `android-postinit.sh`. Never hand-edit icon files under `gen/` — the next hook run overwrites them; change `src-tauri/icons/` instead.
- **Biometric vault unlock shipped with its mandated threat-model entry** (main repo `docs/decisions.md` 2026-07-12 — `provider_kind 0x01` = Apple-Keychain, shared `myne-core` provider). Still open: the **biometric-hardware verification checklist** (a real device must confirm the Keychain read actually prompts and a non-authenticated read fails — the Bitwarden CVE-2023-27706 class) before the gate is presented as trusted. The OS Face ID sheet is unreachable from the flow-logic tier; the manual device checklist owns it.
- **iOS background-execution limits** — Argon2id at `m=256 MiB, t=3, p=2` may exceed mobile background-task budgets. Calibrated lower-cost params for unlock are documented in `decisions.md` 2026-04-26 ("middle-ground between SN004 64 MiB and research recommendation 1 GiB; works on mid-tier mobile ≈2-3s"); verify on real devices early.
- **Tauri Mobile capability ACL is per-platform** — iOS and Android entitlements differ; the desktop `capabilities/default.json` may not be a 1:1 fit. Audit the mobile-specific permission model when Phase 3 begins.
- **Giving a shared primitive an ARIA role makes every existing caller's missing name a defect, so the name has to become required in the same change.** `mobile/src/components/inputs.tsx`'s `Segmented` was four `div`s with an `onClick`: no role, nothing to announce, nothing to name. Adding `role="radiogroup"` to the wired form and leaving `ariaLabel` optional gave its five untouched callers an announced group with `aria-label={undefined}`, which is worse than the unannounced divs, and `tsc` had nothing to say because the prop was optional. The fix is a discriminated union, `{ onChange: (i: number) => void; ariaLabel: string }` against `{ onChange?: undefined; ariaLabel?: undefined }`, which makes the compiler name each site (six, here). The same shape waits in any primitive that grows `role`, `aria-checked` or `aria-describedby` while its describing prop stays optional. myne-md/myne#508.
- **A settings sentence may not describe a mechanism that is not running, and one predicate gates all of them.** Mobile rendered "Reminders are registered through \<date\>" in 32 locales while `mobile/src/lib/reminderPass.ts` had no production caller, so nothing was registered with any OS. Gating that one sentence is not the fix: `ExactAlarmBlock` beside it offered to make delivery precise and asked Android for `SCHEDULE_EXACT_ALARM` to do it, for the same absent delivery. `remindersReachTheOs()` in `mobile/src/lib/reminders.ts` is the one predicate both read, and `mobile/tests/reminders.test.ts` asserts it agrees with what `scripts/check-unwired.mjs` records, so wiring the pass cannot land without flipping it. A control may still ship ungated where the preference is real; what may not ship is a sentence claiming the bound is in force.
- **A spec whose `useTranslation` is stubbed to echo its keys makes every copy assertion in it vacuous, and a header claiming otherwise is not a guard.** `mobile/tests/components/IdentityFlowAccept.test.tsx` asserted in its own header that a second assertion is what stops an echoed key from passing while rendering nothing, and no such assertion existed: the only occurrences of the catalog path in the file were inside that comment. So renaming or deleting `sync.nameGate.label` left the spec green while the phone rendered the raw key on the step that gates an accepted vault, which is the worst place in the flow to lose a string. The flow-logic tier's `mock-ipc.ts` echoes keys the same way, so any spec there that asserts user-visible text owes an assertion that the key itself exists in `locales/en/common.json`, otherwise it is testing the stub rather than the product. Proved by injection: a bogus key now fails the spec. The general shape is that a test double which returns its input can never fail a "did the product show the right thing" assertion, so the assertion has to reach past the double to the catalog.
- **A flow-logic MOTION assertion has to click and read inside ONE `page.evaluate`, waiting only on microtasks.** React commits a discrete event in a microtask, and a `requestAnimationFrame` callback cannot run until the current task's microtasks have drained, so a read after two `queueMicrotask` hops lands after the commit and before the frame (two, because React's own flush is queued first). Reading after `locator.click()` is a race, and the first version of the briefing spec in `tests/flow-logic/onboarding/create-vault.flow.ts` read `present: false` because React had not committed yet (myne-md/myne#868). Waiting a frame instead is worse rather than safer: the flip to `1fr` happens in that frame, so the assertion reads the END state and pins nothing about the entrance. - **Retiring a shared function owes the OTHER tiers of BOTH clients, not just the unit suites.** myne-md/myne#900 retired `deriveSyntaxTokensForTheme` (shared into mobile through the `@myne/syntax-theme` alias) and moved the rule into a new `@myne/theme-canon` module. The two Vitest suites were updated, both apps were correct, and `mobile/tests/flow-logic/settings/custom-themes.flow.ts` plus `custom-themes-unlock.flow.ts` still asserted the deleted output (`--syntax-keyword === "var(--_syntax-keyword-dark)"`), so the change would have turned the CI `mobile-flow-logic` step red on three assertions while every unit test stayed green. The flow-logic tier reads the SAME inline properties the unit suites do, through `rootCustomProps`, so it is a second place a shared apply-path change has to be checked: grep the whole `mobile/tests/` tree for the removed behaviour's OUTPUT, not only for its name.

- **`openNote` replaces the open buffer and saves nothing, and mobile has no autosave.** `EditorFlow`'s `openNote` assigns `editorText`/`editing`/`loadedTextRef` unconditionally; the only writers of the note on disk are the background flush, `saveNote`, and the save-then-open helpers. So a screen that switches the open note by calling `openNote` directly silently discards whatever the user had typed, and there is nothing to recover from: the bytes exist only in RAM, with no snapshot, no trash entry and no synced copy. `openRelated` (save the existing note first) and `openFromList` (which also creates a brand-new non-empty note first) exist for exactly this and are what every list surface calls. Two call sites walked into it in one change (myne-md/myne#886's transcript Save-as-note), and one pre-existing one (`task.noteId`) has the same shape.
