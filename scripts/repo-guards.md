# Repo guards

The full roster behind the root [`AGENTS.md`](../AGENTS.md) section "Repo guards (what blocks a commit, and what blocks CI)". The root file keeps a compact index; this file is the row-by-row map, with guard names repo-relative to the repository root. The guard's own header comment is the authority when it fires.

It lives under `scripts/` rather than `myne-agents/docs/dev/` because the rows cite private companion paths, and `myne-agents/docs/` is the CC-BY subtree that `check-private-path-refs.mjs` keeps free of them.

Most of `scripts/` is not tooling: it is the machine-checked half of the rules the root file states in prose. Each guard exists because the failure it catches is invisible to every compiler: a TS string literal that no `match` arm answers, a `std::fs` call that compiles for wasm32 and dies at runtime, a value in the served bundle that should not be there. They are zero-dependency and hand-runnable (`node scripts/<name>.mjs`, `bash scripts/<name>.sh`); every one carries a header comment explaining the failure it prevents, which is the thing to read when it fires.

The root file's rule against hand-typed counts applies here: a number appears only where the guard itself prints it, and a stale one is deleted rather than corrected. The `check-i18n-coverage.mjs` row records the worked example.
