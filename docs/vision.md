# Myne — Vision

## Tagline

Myne is the only open-source markdown notes app where your files stay plaintext-readable after decryption, where backlinks and graph are first-class, where signup requires no email, and where sync is a server you run yourself, on the same open code as the client.


## The Problem

Privacy-aware users who want Obsidian-like flexibility face an impossible choice today. Either they self-censor inside Obsidian — keeping sensitive thoughts out of the app entirely because notes sit in plaintext on disk (a recurring forum sentiment: *"I will only use Obsidian for superficial information"*) — or they duct-tape together Obsidian + Cryptomator + Syncthing, a fragile three-tool stack where mobile barely works, IndexedDB caches leak plaintext outside the encrypted volume, and performance collapses on large vaults. The encrypted-first alternatives don't fix it either: Standard Notes paywalls markdown and has no backlinks or graph; Notesnook is rich-text-first and stores notes in its own format rather than plain markdown files; Joplin's E2EE is off by default, leaks timestamps, and its plugin ecosystem doesn't work on mobile; Logseq deprecated on-disk encryption entirely. There is no app that combines real built-in encryption with Obsidian-grade markdown flexibility — and the workarounds force users to choose between privacy and the way they actually want to think.

## Target User

**Primary** — the technical Obsidian power user who currently routes around Obsidian's lack of native E2EE. They run Obsidian + Cryptomator + Syncthing, pay for Obsidian Sync uneasily, or self-censor inside the app entirely. They read r/PrivacyGuides, have self-hosted at least one service, can manage a master password and a 24-word recovery phrase. They want Obsidian-grade flexibility without the privacy compromise — and they will read the protocol spec before they install.

**Secondary**: everyone else, including users who don't actively think about privacy. Myne has no plaintext mode for your vault and no opt-in encryption toggle. Built-in privacy is the default for every user, not a feature surfaced to a niche. (The plain-file editor opens a user's own separate on-disk `.md` files outside the vault; it never turns a vault note into plaintext. See `decisions/clients/0625`, `threat-model.md` §7.) The desktop's opt-in diagnostic log and its panic crash record are the same kind of named carve-out, both bounded and stated in `threat-model.md` §7: the log is written only while the user has switched it on, and the crash record whether or not. A casual user who picks Myne because it looks like a clean, fast markdown notes app gets the same zero-knowledge guarantees as the threat-model expert without ever opening the settings. Privacy is not what the app sells; privacy is what the app *is*.

## The Wedge

Myne is the only encrypted notes app where the entire stack — protocol, client, sync server — is open source, and where your notes stay plain markdown after decryption. If you stop trusting us, you self-host. If you stop using us, you walk away with your files into any editor on your machine. There is no proprietary format, no migration tool required, no lock-in.

One qualification, stated here rather than buried: a **browser** client is delivered from a server on every page load, with no signature the browser checks — a materially weaker delivery channel than a desktop build the user downloads once and keeps, and one that gives up a guarantee the native clients keep. (The desktop build is not signed either, and this sentence said it was until 2026-08-25: `decisions.md` entry 0534. What the native channel has is persistence, not verification. The artifact stays on disk, so a substitution reaches only whoever downloaded during the window and the file is still there to compare by hand against the published hash list. A page is re-sent every visit and leaves nothing behind.) What that costs, exactly and against which adversary, is `threat-model.md` A15 / TB11; it is not restated here.

## Success Criteria

Tiered, with both numbers and qualitative outcomes.

**Minimum success — the personal-utility floor.**
- I dogfood Myne daily for at least 6 months without losing a note.
- v1.0 desktop ships within 9–12 months of project start.
- Protocol spec and threat model are public on day one of v1.0.

**Modest success — community validation, year 1.**
- 1,000+ GitHub stars within the first year of public release.
- A few dozen self-hosted instances run by people we don't know.
- A revenue path that is not a hosted service Myne operates. **This row is deliberately left open**, and the target it replaces ("50–100 paying users on hosted sync") is withdrawn with the offering, not met: Myne offers no sync service, so there is nothing to pay for (`decisions/sync/0696`). Naming a new number is a decision this project has not made.
- At least one r/PrivacyGuides forum thread recommending Myne unprompted.

**Stretch success — sustainable small business, year 2–3.**
- 5,000–10,000 GitHub stars.
- Listed on privacyguides.org's notebooks recommendation page.
- A sustainable funding path that does not depend on Myne operating a service for its users, enough to fund continued development without external capital. **This replaces "1,000+ paying users on hosted sync", which is withdrawn with the offering** (`decisions/sync/0696`). Donations were also stopped (2026-10-16), so the mechanism is open rather than chosen.
- Mobile and web clients shipped.
- Protocol spec reviewed informally by at least one external cryptographer or security researcher without a serious flaw being found.
- Community-contributed translations in 3+ languages.

**What success deliberately is not**: VC funding, hyper-growth, mass-market adoption, or feature parity with Notion. Myne aims to be a small, self-sustaining, independent tool that outlasts the founders' attention span by being open enough that someone else can pick it up.

## What Myne Is Not

The list of explicit non-goals is longer than usual because privacy products die from scope creep more than from missing features. These are not "maybe later" — they are commitments the team makes to itself.

- **No VC funding, no acqui-hire exit.** Myne will not raise venture capital. The Skiff shutdown in 2024 is the canonical cautionary tale: VC pressure forced a Notion acquisition, the product was killed inside 12 months, and 2 million users lost their notes home. Bootstrapped, self-sustaining, slow growth is the only path that aligns with a privacy promise. ("Profitable" said this until 2026-10-16; with no paid tier and donations stopped, the funding mechanism is an open question rather than a chosen one, and a word that carries an unbacked claim does not belong here.)
- **No proprietary format.** Notes are plain markdown after decryption. No custom block model, no internal database that "owns" your content, no export tool needed. If Myne disappears, your files are already in the format every editor understands.
- **The recovery phrase is a permanent identity credential, and a browser may now ask for it.** The 24-word phrase unwraps an independent copy of the same persistent `root_key` on `MYV1`/`NTV5`/`NTV6`/`NTV7` vaults, so changing the password does not invalidate it and no rotation command exists: a leaked phrase has no in-app remedy. **Since 2026-10-22 a single identity phrase replaces a new vault's own phrase**, sealing that vault's `root_key` to the owner's person key (`decisions/protocol/0717`, `decisions/storage/0723`): one phrase then opened every vault the person owns, on any device, which widened the blast radius the rest of this bullet is about from one vault to all of them. **Since 2026-10-30 the blast radius is the identity again rather than the content** (`decisions/protocol/0758`, myne-md/myne#938): the `NTV8` birth generation drops the person wrap, so no phrase opens a vault written by this version, and what a stolen phrase buys is the ability to BE that person (register a device, enumerate the account's vaults, sign as them) rather than to read a note. Vaults born before that change keep their wrap and their phrase path until their owner upgrades them, which the client does silently on the next unlock (`decisions/protocol/0758` §10.4.3). The vault password still works independently, and a vault created before the identity change keeps its own phrase until its owner upgrades it explicitly. Three commitments have been made about it in served code, and the record is the point. From 2026-07-26 to 2026-08-15 the phrase was **never** to be generated by, displayed by or typed into served code, which removed account creation and phrase recovery from the web client and gave users a structural inference: no Myne page asks for your 24 words, so a page that asks is fake. That inference was the strongest anti-phishing property this design had, and 2026-08-15 **spent it** so that a browser-first user could create an account and recover one. It kept one restriction back, the phrase as a device-enrolment credential, and 2026-10-18 **retires that too**: it was the reason one credential had two code paths, and a runtime capability gate was never the stronger mechanism. So there is no rule left to state, and the honest sentence replaces it: **Myne can ask for your 24 words in a browser, including to add a device, so check the address before you type them, and prefer a native client for creation, recovery and enrolment.** What remains is disclosure rather than containment, and `threat-model.md` A18 records the cost in full. The unlock-gated, read-only recovery drill that used to sit in Settings was withdrawn on 2026-10-28 (`decisions/security/0747`, myne-md/myne#935): it was a second place a browser asked for the words outside a flow the user started, and the only sentence the product keeps about the phrase now sits on the backup-success screen, with no control beside it. (`decisions.md` 2026-07-26, reversed in part by 2026-08-15 entry 0514, completed by 2026-10-18 entry 0704.)
- **Mobile browsers are refused, not degraded.** The Argon2id parameters are AAD-bound and read from `vault.meta`, so they cannot be lowered for a constrained device without producing a vault no other client can open — and iOS Safari cannot reliably allocate the 256 MiB the baseline requires. A mobile browser therefore gets an honest refusal pointing at the native app, never a quietly-weakened derivation. Weakening the KDF to fit a device is the exact trade this project does not make.
- **Real-time collaboration now ships (reversed 2026-10-10).** This bullet read "No real-time collaborative editing in v1" and deferred it to "Phase 4 at the earliest". That commitment is **reversed**: real-time co-editing, on the same person's own devices and between different people sharing a vault over the B2B substrate, ships in the next release. It builds on the Automerge CRDT note-type (`decisions/sync/0465`, `decisions/protocol/0466`) and a live-awareness transport (downstream SSE plus upstream authenticated POST on `/sync/awareness`, not WebSocket). The accepted metadata cost (active-note presence, active-edit timing, and, for shared vaults, a temporal co-editing graph) is recorded in `threat-model.md` §7 and the AS24 asset. Single-user multi-device sync remains the v1 baseline; this adds a live plane on top of it, it does not replace it.
- **No plugin ecosystem in v1.** Obsidian's plugin model is its biggest strength and the largest privacy hole — plugins can read, write, and exfiltrate the entire vault. Myne will not ship a plugin API in v1, possibly never. If it lands, it will be sandboxed and capability-scoped from the first design — not bolted on after the fact. **The external MCP connection (myne-md/myne#923) is not that API, and the distinction is the capability scoping this bullet asks for rather than a naming preference**: a connected tool supplies no code to the app, holds no key, and can call only a closed verb list over the notes inside a scope the user approved, with no delete, no rename and no attachment access; revoking the grant or closing the door ends it, so it cannot outlive the surface it reaches through.
- **No mobile in Phase 1.** Tauri (Rust core) desktop is the v1 target. iOS and Android come in Phase 3 — on Tauri 2 Mobile, reusing the same Rust core and React UI (`decisions.md` 2026-05-01 supersedes the earlier React Native choice) — after the desktop client and sync server are stable. Trying to ship four platforms with two people is the silent killer in this category (Turtl, Laverna).
- **No feature paywall in the local app.** Everything that runs locally — editor, links, graph, search, encrypted storage — is free, and there is nothing else to buy: sync is a server you run. Standard Notes paywalling markdown rendering is the explicit anti-pattern. (The clause "the paid tier is exclusively the hosted sync convenience" is withdrawn with the offering; `decisions/sync/0696`.)
- **No email at signup. No email recovery.** Account identity is a number; recovery is a 24-word phrase the user holds. **A person account's number is DERIVED from that phrase rather than generated** (`decisions/protocol/0718`), so it cannot be lost and it is not a secret, and a vault born from the identity has no account number of its own. A vault created before that change keeps its own generated number. If both are lost, the data is gone, and we cannot help. This is a hard line. Adding email recovery later would silently invalidate the zero-knowledge claim. **Rewritten 2026-10-30 (myne-md/myne#938, `decisions/protocol/0758`), because this bullet used to promise two recoveries and now promises one.** The phrase recovers the **identity**: the same 24 words derive the same person keypair and the same account number on a new device, so a lost device costs a re-install and never the person. It recovers **no vault content at all**. An `NTV8` vault seals `root_key` under the password wrap alone, with no phrase wrap and no person wrap in the frame, so a forgotten vault password means that vault is gone and no support remedy exists. The old sentence read "if both are lost, the data is gone", which was true of a vault that carried a phrase wrap and is now true of the password alone. This is a deliberate trade rather than a regression: a second way into a vault is a second way into a vault, and the phrase had to be reachable on the daily path for it to stay one, which is exactly where it must never be.
- **No closed-source components.** Client, sync server, protocol spec, build pipeline — all open source. "Open core" is not the model. There will be no proprietary "enterprise" build with extra features.
- **No Notion-style feature creep.** No databases, no kanban boards, no whiteboard, no embedded apps, and no calendar that owns its data. Markdown notes, files on disk, bidirectional links, graph. That is the entire product surface. Users who want a database can keep their database and link to it from a note. **Amended 2026-11-07 (myne-md/myne#1037).** This bullet read "no calendar", which refuses a construct that OWNS its data: a store, a schema, a sync unit, a network path. An event in Myne is an ordinary note (`kind: event` plus a frontmatter vocabulary, `docs/spec/markdown-dialect.md` §3.10) rendered by a pane, so it owns nothing the note envelope did not already own, and `.ics` exchange is a user-initiated file read and write with no network and no third-party origin. The reading is the one `decisions/storage/0744` recorded for the board, applied with the user present: what stays refused is a calendar that becomes a second store (`decisions/storage/0792`).

## Phase 1 Scope

**What v1.0 is.** A single-user Tauri (Rust core) desktop app:

- Encrypted markdown blobs on disk — one ciphertext file per note
- Master password derived via Argon2id and the only credential that opens a vault (`NTV8`); BIP39 24-word recovery phrase naming the person, which derives their identity and their account number and opens no vault
- CodeMirror 6 editor with live markdown and `[[wikilinks]]`
- Full-text search across decrypted notes
- Backlinks pane ("which notes link here")
- Minimal graph view (d3-force layout + hand-rolled canvas render, separate panel, lazy-loaded)
- Obsidian vault importer (`.md` files, YAML frontmatter, `[[wikilinks]]`)

**Definition of done.** v1.0 ships when a real user can install the desktop app, generate an identity phrase, write notes for 30 days, deliberately lose their **device**, recover their **identity** on a fresh install from the phrase alone, open the vault on that device with the password they kept, and at no point have plaintext touched the disk outside the in-memory editor session (user-initiated export excepted, as are the desktop's opt-in diagnostic log and its crash record; see `threat-model.md` §3 TB3 and §7). **Rewritten 2026-10-30 (myne-md/myne#938, `decisions/protocol/0758`).** This read "deliberately lose their password, recover the vault from the phrase", which is now a flow the product does not have and must not imply: the phrase opens no `NTV8` vault. The half that must work is the one that still does, and it is the harder half to get right, since it crosses two devices, a server and a signed identity.

Everything else, mobile, web and plugin API, is explicitly out of scope for v1.0 and lives in later phases. **The managed hosted account and paid tier are no longer planned at all** rather than deferred: Myne offers no sync service (`decisions/sync/0696`). Real-time collaboration, previously on this list, is **pulled forward** and ships in the next release (see the reversed bullet above). **B2B async sharing was the first exception** (`design-notes/protocol/0592`): the person-level identity substrate (keypairs + per-recipient wraps + a shared roster) landed with the invite relay and cross-device roster propagation, and the live-co-edit transport now builds on it. (Self-hostable multi-device sync is itself the v1 commitment; see the Decisions-Log "Sync" note.)

## Decisions Log

A record of the choices made while drafting this document, captured for the next reader.

**Resolved**
- **Project name kept as Myne** for now (placeholder, not branding-final).
- **Tagline retained from the project-advisor evaluation** with the explicit "Mullvad-style" reference removed; the no-email property is preserved in plain language.
- **Problem framing combines self-censorship + workaround stack + critique of existing E2EE apps.** All three are load-bearing; dropping any one weakens the case.
- **Two personas, with privacy as default for both.** Primary is the technical Obsidian power user; secondary is everyone else, who gets E2EE without opting in. There is no plaintext mode for the vault. (The plain-file editor opens a user's own separate on-disk files outside the vault; `decisions/clients/0625`, `threat-model.md` §7. The desktop diagnostic log and crash record are the same carve-out.)
- **Wedge is portability + open source full stack** (alternatives `b` + `c`) rather than competitor takedown or trust-only framing.
- **Success criteria tiered (Minimum / Modest / Stretch)** with both numerical and qualitative outcomes. Numbers anchored on the audience-sizing analysis (5k–30k global power users) and the Notesnook benchmark (~14k stars in ~2 years OSS).
- **Anti-features include eight commitments**, deliberately longer than typical because the team treats scope creep as the primary failure mode for privacy products. (It was nine until 2026-10-10, when the "no real-time collaborative editing" commitment was reversed; see the reversed bullet in "What Myne Is Not".)
- **Phase 1 includes a minimal graph view** (lazy-loaded d3-force panel) — the wedge sentence promises graph as first-class, and v1 has to credibly back that.
- **Definition of done is the recovery flow**: lose the device, recover the identity from the phrase on a fresh install, open the vault with the password, plaintext never on disk. Identity recovery is the highest-risk piece of the project; the DoD reflects that. (It read "lose the password, recover from the phrase" until 2026-10-30; `decisions/protocol/0758` retired the content half, and `threat-model.md` A5 records the cost.)

**Deliberately deferred**
- AI features: **admitted, and the condition they were admitted under has since been superseded** (2026-08-09). AI was first reconsidered on 2026-07-01 under one exact condition: *a fully local LLM with no provider call*: and the local-ai epic (MYND-406,412) shipped on-device summarize / auto-tag / writing-assistant / voice-to-text transcription (MYND-270) behind Candle against it. **That condition no longer holds.** A user may now name an AI **provider**: either a model runtime running on their own machine (reached over loopback: nothing leaves the device) or a remote service such as Ollama Cloud or OpenRouter (where note text does leave the device). Both are **opt-in and default off**, both require an explicit consent step naming what is sent, and the surfaces that fire *without* the user asking: ghost-text, auto-tag: can never reach a remote provider at all. Two things hold, the first now amended: **Myne downloads a model only when the user asks it to, from Myne's own artefact origin, which keeps no IP logs and no analytics** (models not fetched on demand are side-loaded from the user's own disk; this supersedes the never-downloads clause of 2026-08-09, `decisions/ai/0628`), and **nothing is sent anywhere until the user names a provider**: that is the invariant that replaced "zero networked dependency", which the CI gate never actually proved (it is a crate-name denylist, destination-blind; `decisions.md` 2026-08-04). It ships in the default build as a **runtime opt-in, default-off** (Settings → Developer → AI); a `--no-default-features` build is the AI-free auditable binary (`decisions.md` 2026-07-02). What survives of the original line: **no telemetry, no model download by Myne that the user did not ask for, and no egress the user did not ask for.** The one deliberate exception, added 2026-10-07, is the desktop self-update check: a **default-on, user-disablable** fetch of a signed version manifest from Myne's own origin (which keeps no IP logs), carrying only the running version and platform, never notes or an account (`decisions/clients/0649`, `docs/threat-model.md` §7). (See `decisions.md` 2026-08-09 for the supersession and its costs, 2026-07-01 + 2026-07-02 for the history, and `threat-model.md` §3 TB12/TB13 + §1 A16/A17 + §7 "Local AI"; the model runtime's key-isolation sidecar is a hardening still owed, and its recorded plan conflicts with a loopback provider: see §7.) *Note for the reader tracking this clause: the "never downloaded" wording was already narrowed twice: for transcription (2026-07-19) and the auto-tag model (2026-07-31): and neither supersession amended this sentence. This edit reconciles all three at once, so the drift predates the provider work.*
- Real-time collaboration (CRDT, Automerge): **reversed 2026-10-10**, it ships in the next release (see the reversed anti-feature bullet above); no longer deferred.
- Plugin API — possibly never; if it lands, sandboxed and capability-scoped from the first design.
- Mobile — Phase 3.
- **Web, reconsidered (2026-07-26).** A desktop-**browser** client is being built, in-repo at `web/`, compiling the same UI tree and the same Rust crypto core (to wasm) as the desktop client. It is deliberately narrower than the native clients: no quick-unlock, no backup import/export, and none of the affordances that need the operating system. It requires sync, because the browser is a window onto a synced vault rather than a place a vault lives. Account and vault creation, phrase-based **identity** recovery, and phrase-credential device enrolment were out of scope until 2026-08-15 (creation and recovery) and 2026-10-18 (enrolment), and all three ship (`decisions.md` 2026-08-15 entry 0514, 2026-10-18 entry 0704). Phrase-based **vault password** recovery is a fourth thing and it no longer exists on any client: since `decisions/protocol/0758` no phrase opens an `NTV8` vault, so a browser recovers a person and never a note. Mobile browsers stay out of scope. The trust cost is real and is recorded as an adversary and a boundary rather than a footnote (`threat-model.md` A15 / TB11); the decisions are dated 2026-07-26 in `decisions.md`.
- **Sync, reconsidered (2026-07-18).** Single-user multi-device sync is the v1 commitment (see the real-time collaboration bullet above, reversed 2026-10-10), and the **self-hostable open-source sync server ships in Phase 1**, it is in production hardening now (`sync-protocol.md`; the 2026-07-16/17 sync entries in `decisions.md`). The **managed hosted account and paid tier are withdrawn, not deferred**: Myne offers no sync service it is the operator of (`decisions/sync/0696`, 2026-10-16), so the paid tier the 2026-07-18 entry left to Phase 2 is no longer on any roadmap. (See `decisions.md` 2026-07-18.)

**Open risks to revisit**
- Recovery-phrase-only model: Standard Notes and Bitwarden both bleed users at this exact step. Worth checking 12 months in whether the team holds the line or quietly adds an encrypted recovery file as a compensating control.
- Graph view in v1: tension with the "tight Phase 1" goal. If the implementation slips, demote graph to v1.1 rather than slipping the v1 ship date.
- Audience size: 5k–30k global power users is the inferred ceiling. If the year-1 numbers fall short of the modest-success tier, revisit positioning rather than expanding scope.
